# 🐾 Go Pet Shop

**Go Pet Shop** — это учебный проект интернет-магазина товаров для питомцев, написанный на Go с использованием PostgreSQL.  
Он создан для отработки навыков работы с SQL-запросами, транзакциями и построения REST API.

---

## 🚀 Основная идея

Проект моделирует классический онлайн-магазин с товарами, пользователями, заказами и оплатами.  
Цель — показать полный цикл разработки от работы с базой данных и CRUD-операций до реализации транзакций и аналитики.

---

## 🔑 Возможности проекта

- 📦 Управление товарами (добавление, обновление, удаление, просмотр списка и конкретного товара).  
- 👤 Работа с пользователями (регистрация, получение списка и конкретного пользователя).  
- 🛒 Создание заказов и добавление позиций.  
- 💳 Оформление заказов в транзакции (уменьшение остатков, создание заказа, позиций и транзакции оплаты).  
- 📊 Просмотр истории заказов и аналитики (популярные товары, детали заказов и транзакций).  
- ✅ Health-check для проверки состояния сервера.

## ⚙️ Технологии

## 🛠 Как запустить

1. Клонировать репозиторий:
   `git clone https://github.com/kreslokatalka/go-pet-shop.git`
   `cd go-pet-shop`

2. Настроить окружение: скопировать `.env.example` в `.env` и поправить логин, пароль и имя базы.
`cp .env.example .env`

3. Поднять PostgreSQL и применить миграции:
`docker compose up -d postgres`
`task migrate`

4. Запустить сервер (конфиг `config/local.yaml`, другой выбирается через `APP_ENV`):
`go run ./cmd/app`

5. После этого API будет доступно по адресу:
`http://localhost:8080`, проверка — `GET /health`.

Всё сразу в контейнерах: `docker compose up -d --build` (приложение берёт `config/dev.yaml`).

## 🧪 Тесты

### `tests-manual` и `tests-mockery`

Это два подхода к подмене зависимости в тестах:

- **`tests-manual`** — mock/stub написан вручную: тест сам реализует интерфейс и задаёт нужное поведение. Это просто и позволяет явно контролировать ответы, но при изменении интерфейса ручную реализацию нужно обновить.
- **`tests-mockery`** — реализация интерфейса генерируется Mockery. В тесте с `testify/mock` задаются ожидаемые вызовы, аргументы и возвращаемые значения; ожидания проверяются автоматически. Это уменьшает объём вспомогательного кода, но при изменении интерфейса моки нужно перегенерировать.

Ветки `tests-manual` и `tests-mockery` содержат альтернативные реализации тестов в `internal/handlers/product/products_test.go`. Обе проверяют HTTP-обработчики товаров с подменённым хранилищем и не требуют запущенной базы данных; различается способ создания моков и проверки вызовов.

### Запуск тестов

Из корня репозитория:

```bash
# Все пакеты
go test ./...

# Тесты обработчика товаров с подробным выводом
go test -v ./internal/handlers/product
```

### Перегенерация моков

Ветка `tests-mockery` содержит в `internal/handlers/product/products.go` директиву `go:generate` с зафиксированной версией Mockery (`v2.53.7`). Перегенерировать соответствующий мок из этой ветки можно из корня проекта:

```bash
go generate ./internal/handlers/product
```

Команда создаёт/обновляет `internal/handlers/product/mocks/Products.go`. После изменения интерфейса проверьте сгенерированный diff и запустите `go test ./...`.

## 🧩 Текущие ветки проекта

- **`tests-manual`** — тесты используют ручной мок `ProductsMock` из `internal/handlers/product/product_mock.go`. Поведение хранилища задаётся функциями в тестах; вызовы и их количество не проверяются автоматически.
- **`tests-mockery`** — тесты используют сгенерированный Mockery мок `internal/handlers/product/mocks/Products.go` и `testify/mock`: ожидания задаются через `On(...).Return(...).Once()` и автоматически проверяются.

В обеих ветках тестируются HTTP-обработчики товаров и их ответы; хранилище подменяется моками, поэтому запуск PostgreSQL для тестов не требуется. Ветка `tests-mockery` отличается способом создания и проверки моков, а не набором возможностей приложения.
